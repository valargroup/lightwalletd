## What the measurements show

The polling cache is the best defense against ordinary wallet status polling.
At the median baseline rate, a ten-second sample caused 127,169 backend JSON-RPC
requests and connections. The candidate served nearly four times as many gRPC
requests while issuing only nine backend requests and connections. The cache
still checks the tip, keys tree state by the exact height and hash, clones cached
protobufs, and bounds detached shared refreshes with a timeout.

The subtree hash cache removes repeated protobuf decoding from
`GetSubtreeRoots`. It still performs one `z_getsubtreesbyindex` call per client
request, so backend connection reuse remains independently useful. Its large
gain is a warm-cache steady-state result. The first request for a completing
block still pays for one decode.

Backend keepalive is broad and small in code size. The median baseline created
109,436 TCP connections during a ten-second sample. The candidate created 15
while completing more requests. Its normalized server CPU cost was 4.7% higher
in this localhost test, but throughput, latency, allocation pressure, and TCP
churn all improved materially.

Direct hex decoding is valuable specifically for large uncached backend
responses such as full blocks and raw mempool transactions. It keeps a fallback
for escaped JSON strings. The approximately 1 MB block workload showed a clean
24.8% throughput improvement in a separate error-free rerun.

In-place range filtering is a smaller but consistent win across both expensive
Sapling-only filtering and the default response shape. It is worth advancing
after the larger candidates, with the default-shape result treated as marginal
enough to reconfirm on a production-like host.

The mempool branch is more important than its 3.8% throughput gain suggests.
The baseline sorts a shared published slice from concurrent request handlers.
Under the race detector, the baseline produced 14 data-race warnings in
`MempoolFilter`; the candidate produced none. With 3,900 of 4,000 txids excluded,
the candidate returned exactly 100 transactions per request in all samples.
The racing baseline varied from 114.3 to 164.2, increasing response work beyond
the requested result.

Direct range streaming should not advance. Removing the channel also removed
useful overlap between block production and gRPC encoding. It regressed both a
long stream and a one-block stream despite slightly reducing allocations.

## Method

The harness ran actual `lightwalletd` binaries and real concurrent gRPC clients
against a deterministic local JSON-RPC backend. Before every sample,
`measure.sh` started a fresh server, warmed the requested operation, reset
backend counters, and captured Go process metrics around the load interval.

The generated inputs were:

- a 2,048-block dense compact cache with 64 transactions per block;
- a 2,048-block sparse compact cache with one transaction per block;
- a parser-valid raw block response of approximately 1 MB;
- a shuffled 4,000-entry mempool with 3,900 exclusions; and
- 64 Sapling subtree roots.

The compact cache exercises the real on-disk cache and protobuf paths. The
synthetic backend data is deterministic and sufficient for these handlers, but
it is not a consensus-valid substitute for Zebra or zcashd integration tests.
The local setup intentionally removes Internet and TLS variance so it can
attribute differences to `lightwalletd`. Absolute public-server capacity and
latency should not be inferred from these rates.

## Environment and validation

- macOS 26.6.2 (25G83), arm64
- Apple M3 Ultra, 20 performance and 8 efficiency cores
- Go 1.25.0
- one gRPC connection per load worker
- candidate-specific unit tests plus `go test ./...`
- targeted race tests for the cache paths
- process-level race-detector A/B for the mempool path

The reusable harness and standard workload matrix live in
`contrib/bench/lwdlab`. No DigitalOcean resource was needed for this comparative
pass. A dedicated remote host with a real synced backend is most useful as a
second confirmation for the smaller range-filter result, not for distinguishing
the large polling, subtree, keepalive, or raw-decode effects.
